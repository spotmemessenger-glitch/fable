# UI pattern ledger

Every pattern we adopt or reject, with the evidence behind it. Written by the
`proven-pattern-check` skill during builds. **Refine entries in place — never
duplicate.** A tier can be revised when better evidence appears; edit it and note
the change with a date.

## Entry format

```
### <pattern name>
- **Tier:** A | B | C
- **Observed in:** <product — scale, from store-intel; product — scale>
- **Claim:** <what the pattern is said to do>
- **Source:** <url, or "none — convergent observation only">
- **Verified:** <YYYY-MM-DD>
- **Our call:** adopt | adapt | reject — <why>
```

## Tier definitions

- **A** — published experiment with a reported lift, primary source cited.
- **B** — observable in several named products at known scale; convergent design.
  Strong, but *not* a measured lift and must never be described as one.
- **C** — common advice with no verifiable result. Treat as a hypothesis to test,
  regardless of how confidently the source states it.

Never attribute revenue to a UI pattern. That a large product ships a pattern is
an observation about the product, not proof the pattern produced the revenue.
