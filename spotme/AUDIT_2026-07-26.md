## CRITICAL FINDINGS

### 1. Video Persistence Bug (P0 — Ship Blocker)

**Severity:** CRITICAL | **Impact:** Data loss | **Root Cause:** Unbounded media in localStorage

**Finding:**
`spotme/web/src/store.js` `save()` persists message data URLs (including video, cap 40 MB) to localStorage (~5–10 MB quota). One large video + backlog → throws → catch silently swallows → **entire room stops persisting, conversation vanishes on refresh, no error signal**.

**Evidence:**
- Code: `store.js:save()` calls `JSON.stringify(msgs)` with full media blobs
- `stripDerived()` removes only `reactions`, NOT media data
- Quota exceeded → catch on line ~200 silently logs nothing
- Convo stays broken while video in last 500 messages

**Remediation:**
```javascript
// store.js: stripDerived() — add media removal
function stripDerived(msg) {
  const out = { ...msg }
  delete out.reactions
  delete out.data  // ADD: remove all media
  return out
}
```

**Timeline:** 1 day (test: send 40 MB video → refresh → verify chat persists) | **Assigned:** Coder

### 2. Relay Rate Unverified (P1 — Scale Risk)

**Severity:** CRITICAL for budget | **Impact:** 10× cost swing | **Root Cause:** Theory, not measurement

**Finding:**
The server tier cost calculation in [[spotme-server-tier]] assumes **~10% of connections fail UDP hole-punching and require TURN relay**. This is industry-standard for symmetric NAT / carrier-grade NAT, but **Spot Me has NEVER measured it on real cross-network devices**. All verification ran two peers on the same machine (localhost transport).

**Implication at 1M users:**
| Scenario | Annual Cost |
|----------|--|
| 5% relay (unlikely) | ~€10K (Hetzner) |
| 10% relay (assumed) | ~€24K (Hetzner) |
| 15% relay (carrier NAT) | ~€36K (Hetzner) |
| AWS egress, 10% | ~€270K 🔴 |

**Test Required:**
Phone on mobile data ↔ Broadband PC, **measure actual relay rate** in carrier-grade NAT conditions (Jio/Airtel).

**Timeline:** 4–6 hours (setup + 10 runs each) | **Assigned:** Ops

### 3. Cloned Voice → Plaintext to Vendor (GDPR/BIPA)

**Severity:** HIGH | **Impact:** Biometric data leak | **Root Cause:** Feature design

**Finding:**
Voice cloning sends **unencrypted audio to ElevenLabs** (US processor). This is:
- **Art. 9 special-category data** under GDPR (voice biometrics)
- **Biometric data** under Illinois BIPA ($1,000–$5,000 statutory damages per violation, private right of action)

**Current Disclosure:**
- Privacy Policy §3 mentions it (draft)
- No per-feature consent modal
- Stripe payment tied to account (purchased feature)

**Remediation:**
1. Add explicit consent modal before first clone (not buried in Privacy Policy)
2. Clarify data processor (ElevenLabs) + retention (EL default: 90 days)
3. Update Privacy Policy §3 to BIPA compliance level before counsel review

**Timeline:** 4 hours (consent modal + disclosure audit) | **Assigned:** Legal + Frontend

### 5. Backend Architecture

#### Current Design

```
┌─────────────────────────────────────────┐
│ Web App (spotme/web)                    │
│ - Trystero WebRTC (tunneled via public  │
│   BitTorrent trackers)                  │
│ - Vercel Functions (translate, voice,   │
│   TURN creds, username registry)        │
└──────────────────────────────────────────┘
         │
         ├─→ API Layer (Node.js on Vercel)
         │   - /api/translate (Google/Azure)
         │   - /api/voice (ElevenLabs proxy)
         │   - /api/turn (Cloudflare TURN)
         │   - /api/username (Vercel Blob store)
         │
         ├─→ External Services
         │   - Google Cloud Translator (gtx)
         │   - Azure Translator
         │   - ElevenLabs (TTS, STT, clone)
         │   - Cloudflare TURN
         │   - Vercel Blob (username registry)
         │
         └─→ P2P Layer (Trystero + Hyperswarm)
             - Peer discovery (public trackers)
             - Direct WebRTC (when hole-punch succeeds)
             - TURN relay (Cloudflare, 10% of paths)

┌──────────────────────────────────────┐
│ Always-on Relay Node (Proposed)       │
│ - Same spotme/core code as app        │
│ - Joined as non-writer replica        │
│ - Stores room history (no decryption) │
│ - Receives offline deliveries         │
│ - Relays for blocked UDP paths        │
│ - Cost: 2–3 nodes @ €4/mo (Hetzner)  │

```

## APPENDIX C: Scalability Calculations

### Relay Rate Sensitivity Analysis

Assuming 1M users, 10% of users online at any time = 100K connections.

| Relay Rate | TURN Bandwidth | Annual Cost (Hetzner) | Annual Cost (AWS) |
|---|---|---|---|
| **5%** (best case) | 500 Mbps | €10K | €90K |
| **10%** (assumed) | 1 Gbps | €24K | €216K |
| **15%** (carrier NAT) | 1.5 Gbps | €36K | €324K |
| **20%** (symmetric NAT) | 2 Gbps | €48K | €432K |

**Critical test:** Measure actual relay rate on mobile data (Jio/Airtel). Determines whether relay is <€50K or >€300K per year.

### Media Egress Calculation

Assumptions:
- 1M users
- 10% online concurrently
- 10 MB media/user/month (3 photos + 1 video)
- Average session duration: 30 minutes

| Metric | Value |
|---|---|
| Monthly media volume | 1M users × 10 MB = 10 TB/mo |
| Annual egress (R2) | 10 TB × 12 = 120 TB; free tier: €0 |
| Annual egress (AWS) | 120 TB × $0.09/GB = 120,000 GB × $0.09 = **€10.8K/mo = €129K/yr** |

**Winner: R2** (€0 vs. €129K)
